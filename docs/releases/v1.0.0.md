## 🚀 🛰️ Orbit and Launch Alert — v1.0.0

**Initial Release: Rocket Launches & Satellite Tracking**

**Original release date:** 2026-11-04
**Tag:** `v1.0.0`
**Release type:** Initial stable release

Orbit and Launch Alert is a lightweight MeshMonitor script providing emoji-based rocket launch notifications, satellite overpass predictions, and ISS visibility alerts over Meshtastic and MeshCore networks using official launch schedules and orbital data.

It is the space-monitoring companion to [Sky and Sea Alert](https://github.com/maxhayim/meshmonitor-skyandsea-alert): same KISS philosophy, same MeshMonitor integration, independent code and version sequence.

---

## ✨ Features

- 🚀 Worldwide rocket launches from The Space Devs Launch Library 2
- ⏱️ Countdown alerts at T-24H, T-1H, T-15M and scheduled T-0 (all configurable)
- ⚠️ Delay, reschedule, hold, cancellation, and removed-from-schedule alerts
- ✅ Success / failure / partial failure / in-flight alerts, **only when the source reports them**
- 🌎 Filters by country, agency, launch site (`cape` preset for Cape Canaveral + Kennedy), rocket, and mission
- 📏 Optional distance to the launch pad (never presented as visibility)
- 🛰️ Local SGP4 pass predictions: AOS, max elevation and time, LOS, duration, azimuths
- 🌌 ISS and satellite visible-pass estimates (dark sky + sunlit satellite), clearly labeled as estimates
- 📡 Amateur-radio satellites by group or NORAD ID (no invented frequencies)
- 🧾 Persistent notification ledger: no duplicates, even across restarts
- 💾 Atomic, bounded cache with `CACHED <age>` freshness labels and offline operation
- 🔒 Rate-limit handling (429 / throttling / `Retry-After` / exponential backoff / CelesTrak 403)
- 📨 Optional MQTT events (off by default, loop-safe)
- 🧪 Offline demo mode with clearly labeled simulated alerts

## 🌐 Supported Data Providers

| Data | Provider | Notes |
|---|---|---|
| Launch schedules | The Space Devs Launch Library 2 (`2.3.0`) | Free, anonymous (rate limited); optional personal token |
| Orbital elements | CelesTrak GP data (OMM JSON) | Free; cached 12 h by default |
| Propagation | Local, `sgp4` (MIT) | Compiled or pure-Python mode |

No scraping. No shared API keys. No proprietary tracking services.

---

## 🤖 MeshMonitor Compatibility

- **Auto Responder**: `MESSAGE` set → one command, exactly one JSON object `{"response": "..."}` on stdout
- **Timer Triggers**: `TIMER_NAME` set → one notification check; `{"response": ""}` when nothing is due, or `{"responses": [...]}` (max 5)
- `mm_meta` with `name`, `emoji`, `version`, `author`, `source` (MeshMonitor update checks)
- Messages ≤ 200 characters, emoji-led
- Location falls back to `MM_LAT`/`MM_LON`, time zone to `TZ`
- MeshMonitor handles Meshtastic, MeshCore, routing, channels, and retries. Orbit and Launch Alert never transmits on radios directly.

## 📦 Installation

```bash
git clone https://github.com/maxhayim/meshmonitor-orbitandlaunch-alert.git
cd meshmonitor-orbitandlaunch-alert
pip install -r requirements.txt
OLA_MODE=demo python3 orbit_and_launch_alert.py
```

Inside MeshMonitor:

```bash
docker cp orbit_and_launch_alert.py meshmonitor:/data/scripts/
docker exec meshmonitor /opt/apprise-venv/bin/pip install --target /data/scripts/ola_vendor sgp4
```

## ⚙️ Configuration

All settings use the `OLA_` prefix. Key variables: `OLA_MODE`, `OLA_LAT`, `OLA_LON`, `OLA_TIMEZONE`, `OLA_LAUNCH_ALERT_HOURS`, `OLA_LAUNCH_ALERT_MINUTES`, `OLA_LAUNCH_SITES`, `OLA_SATELLITE_GROUPS`, `OLA_SATELLITE_IDS`, `OLA_MIN_ELEVATION_DEG`, `OLA_LOOKAHEAD_HOURS`, `OLA_CACHE_DIR`. Invalid coordinates, time zones, NORAD IDs, and numbers are reported, never silently replaced.

Full reference: `docs/configuration.md` and `.env.example`.

Modes: `demo`, `launches`, `satellites`, `iss`, `orbit_and_launch`.

## ⚠️ Limitations

- Visibility is an estimate (sun ≤ −6°, cylindrical shadow, ≥ 10° elevation). Weather, light pollution, terrain, and brightness are not modeled.
- Launch Library 2 has no "canceled" status; launches that vanish from the schedule are reported as *removed from schedule*.
- Element sets older than 7 days (configurable) are refused.
- Large CelesTrak groups are capped at 20 objects per group by default (MeshMonitor's 30 s script timeout).
- No amateur-satellite frequencies.
- Named time zones on Python 3.8 need `backports.zoneinfo`.

---

## 🔐 Security

- No hardcoded credentials. Optional `OLA_LL2_API_KEY` / `OLA_MQTT_PASSWORD` come from the environment only and never appear in messages or MQTT events.
- Schema validation for all provider data. Errors go to stderr, never to the mesh.
- MQTT off by default, off inside MeshMonitor unless allowed, never republishes MQTT-bridged commands.
